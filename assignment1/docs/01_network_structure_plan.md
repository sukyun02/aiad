## 3. 근거

### 3.1 용어

- **starter**: 제공된 원래 `network.py` 구조(합성곱 1층 + 풀링 + Linear 1개). `baseline.pth`는 이 구조를 학습해 둔 제공 모델이다.
- **cnnA**: 이 문서가 채택하는 4층 CNN의 파일럿 기록상 이름.
- **체크포인트**: 학습이 저장한 `.pth`(가중치)와 짝이 되는 `.network.py`.
- **seed, 독립 학습**: 학습 1회를 구분하는 난수 번호. "seed 0~3"은 서로 독립인 학습 4회다. 공식 `train.py`는 seed를 고정하지 않으므로 실행할 때마다 새 seed와 같다.
- **깨끗한 완주**: 완주했고, 진행률이 100.00이며, 도로 밖 프레임이 0인 주행. 공식 결과의 "완주"는 도로를 잠깐 벗어난 주행도 포함하므로 이 문서는 깨끗한 완주만 센다. 예: 랩타임 42.90초인데 진행률 98.93인 주행은 불합격이다.
- **파일럿 kit**: `aiad/pilot/kit/k`. 공식 학습과 같은 방식으로 학습하고 화면 없이 주행시키는 실험 도구다. 주행은 공식 환경·제어기·지표 코드를 그대로 불러 쓴다. 제공된 `baseline.pth`에서 공식 GUI 결과(45.54초, 중앙선 51.03)를, cnnA 체크포인트에서 공식 주행 코드의 결과(43.16초, 중앙선 76.53)를 소수 둘째 자리까지 똑같이 재현했다.
- **HUD**: 관측 영상 아래쪽 띠(84~95행)의 계기판. 속도·ABS·조향·자이로 막대와 점수 숫자가 그려진다.
- **gate**: kit 명령 `k gate`. 체크포인트 하나를 원래 입력과 조금 바꾼 입력으로 8번 주행시키는 제출 전 점검이다(5.5).

### 3.2 구조와 배치 크기

각 칸은 "깨끗한 완주 수 / 주행시킨 체크포인트 수"다. 모두 kit으로 학습한 결과다.

| 구조 | batch | epoch | 깨끗한 완주 | 비고 |
|---|---|---|---|---|
| 제공된 `baseline.pth` | - | - | 1/1 | 45.54초, 중앙선 51.03, 지그재그 주행 |
| starter 재학습 | 4096 | 100 | 1/5 | 학습 5회 |
| starter 재학습 | 256 | 25, 50, 100 | 0/12 | 학습 4회 × 3시점, 전부 이탈 |
| cnnA | 4096 | 100 | 0/3 | 학습 정확도 0.78, "항상 가속" 수준 |
| cnnA | 256 | 100 | 9/12 | 아래 3.3 |

starter 구조는 갱신 횟수를 15배 늘려도(batch 256, 100 epoch) 학습 정확도가 0.81~0.84에 그치고 한 번도 완주하지 못했다. cnnA는 같은 조건에서 0.96~0.98이다. 다만 깊이, 공간 해상도, 은닉층 중 어느 것이 결정적인지는 따로 실험하지 않았다.

### 3.3 cnnA, batch 256의 epoch별 결과

| epoch | seed 0~3 | seed 0~3 재학습 | seed 4~7 | 합계 |
|---|---|---|---|---|
| 25 | 0/4 | 0/4 | - | 0/8 |
| 30 | - | - | 0/4 | 0/4 |
| 40 | - | - | 1/4 | 1/4 |
| 50 | 3/4 | 3/4 | 3/4 | 9/12 |
| 60 | - | - | 3/4 | 3/4 |
| 80 | - | - | 4/4 | 4/4 |
| 100 | 4/4 | 2/4 | 3/4 | 9/12 |
| 150 | - | - | 2/4 | 2/4 |
| 200 | - | - | 4/4 | 4/4 |
| 250 | - | - | 3/4 | 3/4 |
| 300 | - | - | 4/4 | 4/4 |

- **50 epoch 미만은 부족하다.** 25~40 epoch은 16번 중 1번만 깨끗했다.
- **50 epoch 이상에서는 epoch 수로 안정성이 갈리지 않는다.** 80이 4/4, 100이 3/4, 150이 2/4, 200이 4/4로 들쭉날쭉하다. 더 오래 학습한다고 좋아진다는 근거가 없으므로 100을 유지한다.
- **실패는 학습 단위로 몰린다.** seed 6 하나가 50, 60, 100, 150, 250 epoch에서 실패했고 나머지 세 seed는 거의 전부 깨끗했다. 약한 학습이 걸리면 처음부터 다시 학습하는 편이 낫다.
- **깨끗한 주행의 수치**: 50 epoch 이상의 깨끗한 주행은 랩타임 42.78~43.56초, 중앙선 59~79였다. 전문가 7바퀴는 42.72~43.44초(중앙값 43.02), 중앙선 66~81이다.

"seed 0~3 재학습" 열은 계기판 영역을 잘라내는 층을 앞에 붙인 변형(`cnnA_crop`)이다. cnnA의 합성곱은 원래 영상 아래쪽 15줄을 읽지 않아서 이 변형은 수학적으로 같은 함수이고, seed와 초기 가중치가 같은데도 결과가 갈렸다. 즉 seed 4개짜리 비교에서 1~2개 차이는 잡음이다.

100 epoch의 9/12는 학습 12회 기준이다. 서로 다른 seed는 8개이고, seed로 세면 7/8이다.

### 3.4 그 밖에 확인된 것

- **같은 체크포인트의 로컬 주행은 매번 같다.** CPU와 GPU 주행도 서로 다른 체크포인트 60여 개에서 프레임 단위로 일치했다. 로컬에서 한 번 깨끗하면 로컬에서는 항상 깨끗하다.
- **학습은 재현되지 않는다.** 공식 학습은 seed를 고정하지 않고, kit에서 같은 seed로 같은 구조를 다시 학습해도 loss와 주행 결과가 달랐다. 좋은 체크포인트는 다시 만들 수 없으니 파일을 보관한다.
- **loss나 정확도로는 좋은 체크포인트를 고를 수 없다.** seed 6은 100 epoch에서 seed 4~7 중 loss가 가장 낮았는데 도로를 벗어났다. loss는 "학습이 제대로 돌았는가"만 확인하는 용도다.
- **입력을 아주 조금 바꾸면 다른 궤적이 나온다.** 원래 주행이 깨끗한 체크포인트에 HUD 숫자 지우기나 ±2 픽셀 잡음을 준 주행 50개 중 4개(8%)가 깨끗하지 않았고, 그중 1개는 중단됐다. 완주한 주행에서도 랩타임은 최대 0.7초, 중앙선은 최대 10점 움직였다. 이보다 작은 차이로 체크포인트 우열을 가리지 않는다.

### 3.5 근거의 한계

- 3절의 cnnA 주행 수치는 전부 kit으로 학습한 모델의 것이다. 실행 전에는 공식 `train.py` 기록이 50 epoch 중 30까지만 돌다 중단된 것 하나뿐이었다(epoch 30 loss 22.07, kit은 23.2~24.4).
- "한 번 학습의 성공률 약 3/4"의 실제 범위는 넓다(대략 0.4~0.9).
- 문서의 명령은 저장소 임시 사본에서 1 epoch짜리 학습으로 실행해 보았다: 5.1의 수정과 확인, 5.2, kit을 거친 5.3 학습, 저장되는 파일 쌍과 해시 일치, 5.4의 kit 주행. 공식 주행 코드가 cnnA 체크포인트를 kit과 같은 값으로 주행시키는 것도 확인했다.
- 실행 뒤 확인된 것: 공식 학습 4회의 loss가 모두 기준 범위 안이었고, kit 주행과 공식 주행 코드의 결과가 4회 모두 일치했다. 깨끗한 완주는 4회 중 3회, 랩타임 43.14~43.28초, 중앙선 66.80~77.14였다(11절).
- 확인하지 못한 것: 창이 뜨는 GUI 주행(`infer.py`)으로 cnnA를 돌리는 것, 채점 서버의 장치와 제한(9절), 서버 결과가 로컬과 일치하는지(5.7).

## 4. 이 노트북에서의 실행 규칙

2026-10-06에 python 프로세스가 100개 넘게 떠서 노트북이 두 번 죽었다. 이 문서의 명령은 아래를 지키도록 적혀 있다.

- **torch를 쓰는 명령은 모두 `../pilot/kit/k`를 거친다.** kit은 동시 실행 수와 메모리를 제한하고, 한도를 넘으면 그 실험만 죽는다. 공식 스크립트도 `k job -- ...`으로 감싼다. 예외는 본인이 직접 띄우는 GUI 주행(`scripts/infer.py`) 하나뿐이다. 그때는 다른 학습이나 주행이 돌고 있지 않은지 먼저 확인한다.
- **직접 띄우는 명령은 한 번에 하나만** 실행한다. `&`, `nohup`, `xargs -P`를 쓰지 않는다. kit 명령 하나가 안에서 여러 개를 돌리는 경우(`gate`는 주행 최대 6개, 6절 (b)는 학습 2개)는 kit이 관리하므로 그대로 둔다.
- 실행 전에 `free -h`로 가용 메모리가 6GiB 이상인지 본다(`gate` 전에는 8GiB). 공식 학습 1개는 약 1.6GB, 주행 1개는 약 1.1GB를 쓴다(`/usr/bin/time`으로 잰 최대 사용량).
- **학습은 마지막 epoch 뒤에만 저장한다.** 중간에 끊으면 남는 것이 없다. 학습 중에는 `src/network.py`를 고치지 않는다(저장 시점의 파일이 제출용 사본이 된다). 설정이 틀린 것이 epoch 1의 loss로 확인되면 바로 끊어도 된다.
- **Claude에게 맡길 때**: 학습은 백그라운드 작업 하나로 띄우고 완료 알림을 기다리게 한다. 일반 실행은 기본 2분, 최대로 늘려도 10분에서 끊긴다.
- **본인만 할 수 있는 것**: 창이 뜨는 GUI 주행(`scripts/infer.py`, 결과가 나온 뒤 Esc를 눌러야 끝난다)과 제출 사이트 업로드.
- **끊는 방법**: 본인 터미널에서는 Ctrl+C. kit이 띄운 것을 전부 멈추려면 `systemctl --user stop aiad-pilot.slice`.
- **`assignment1/`을 바꾸는 것은 이 문서의 5절 단계뿐이다**(코드 수정, `models/`와 `docs/logs/`에 쓰기). 그 밖의 실험은 `pilot/` 안에서 한다.

명령은 모두 `assignment1/` 폴더에서 실행한다.

## 5. 실행 단계

### 5.1 `src/network.py` 수정

TODO 표시 줄(`# ===== TODO: (구현 영역) …`) 바로 아래부터 `self.fc` 블록의 닫는 괄호까지(원본 76~116행)를 아래 내용으로 바꾼다. 그 아래의 `# [수정할 때 확인할 것]` 주석과 TODO 영역 밖은 건드리지 않는다.

```python
        # starter(합성곱 1층 + 4×4 평균 풀링 + Linear 1개)를
        # stride 2 합성곱 4층과 은닉층 1개짜리 분류기로 바꾼 구조입니다.
        #
        # [전체 데이터 흐름]
        # B는 한 번에 처리하는 영상 수(batch size)이며, 추론할 때는 보통 1입니다.
        # 원본 입력 (B, 96, 96, 3)은 forward()에서 픽셀을 0~1로 정규화하고
        # 채널 순서를 바꾸어 (B, 3, 96, 96)으로 만든 뒤 self.conv에 전달합니다.
        # conv 출력 → 펼치기(flatten) → 센서 7개 결합 → self.fc → 행동 9개 점수
        # 펼치기와 센서 결합은 아래 forward()에서 이미 처리합니다.
        #
        # [1. 영상 특징 추출: self.conv]
        # Conv2d(입력 채널, 출력 채널, kernel_size, stride)
        # padding=0, dilation=1이므로 출력 한 변은
        # floor((입력 한 변 - kernel_size) / stride) + 1입니다.
        # stride 2 합성곱을 4번 거치며 한 변은 96 → 46 → 22 → 10 → 4로 줄고,
        # 채널은 3 → 16 → 32 → 64 → 64로 늘어 (B, 64, 4, 4)가 됩니다.
        self.conv = torch.nn.Sequential(
            torch.nn.Conv2d(3, 16, kernel_size=5, stride=2),    # (B, 16, 46, 46)
            # 음수는 0으로 바꾸는 활성화 함수입니다. 텐서 크기는 유지합니다.
            torch.nn.ReLU(),
            torch.nn.Conv2d(16, 32, kernel_size=3, stride=2),   # (B, 32, 22, 22)
            torch.nn.ReLU(),
            torch.nn.Conv2d(32, 64, kernel_size=3, stride=2),   # (B, 64, 10, 10)
            torch.nn.ReLU(),
            torch.nn.Conv2d(64, 64, kernel_size=3, stride=2),   # (B, 64, 4, 4)
            torch.nn.ReLU(),
        )
        #
        # [2. 행동 분류: self.fc]
        # forward()가 conv 출력을 펼치면 영상당 64×4×4 = 1024개 특징이 됩니다.
        # 여기에 영상 하단 계기판에서 추출한 센서 특징 7개를 붙입니다.
        # 센서 7개 = 속도 1개 + 바퀴별 ABS 4개 + 조향 1개 + 자이로 1개
        # 따라서 첫 Linear의 입력 크기는 1024 + 7 = 1031입니다.
        # 은닉층(128개)을 한 번 거친 뒤 행동 9개의 점수를 냅니다.
        # 출력 (B, 9)의 각 값은 위 action_classes 순서에 해당하는 행동 점수(logit)입니다.
        # 학습의 CrossEntropyLoss가 logits를 받으므로 마지막에 Softmax를 넣지 마세요.
        # 추론에서는 가장 큰 점수의 행동을 선택합니다.
        self.fc = torch.nn.Sequential(
            torch.nn.Linear(64 * 4 * 4 + 7, 128),
            torch.nn.ReLU(),
            torch.nn.Linear(128, self.n_classes),
        )
```

### 5.4 주행 판정

```bash
M=$(ls -t models/2*.pth | head -1); M=${M%.pth}; echo $M      # 방금 저장된 쌍. 예: models/20261006_191515

../pilot/kit/k eval $M.pth --slot | tee docs/logs/eval_$(basename $M).json     # kit 주행 (10~25초)
../pilot/kit/k official $M.pth                                                 # 공식 주행 코드 (10~25초)
```

`k eval`은 JSON 한 줄을 출력한다.

- 정상 예: `{"status": "finished", "lap_time": 43.160000000000004, "progress": 100.0, "center": 76.53, …, "max_offset": 2.32, …, "offroad_frames": 0, …}`. `lap_time`은 43.16으로 읽는다.
- 불합격 예: `"status": "aborted", "lap_time": null, "progress": 53.2, …` 또는 `"status": "finished", "progress": 98.93, …, "offroad_frames": 22`.

**합격 기준** (모두 만족):

- `status`가 `finished`, `progress`가 100.0, `offroad_frames`가 0
- `lap_time`이 43.6 이하
- `center`가 30 이상 (55 미만이면 합격이지만 이례적이므로 기록에 표시한다)
- `max_offset`이 6.67(도로 반폭) 미만

`k official`은 `scripts/infer.py`와 같은 코드를 창 없이 돌려 `주행 결과: 진행률 … | 중앙선 유지 … | 랩타임 …`을 출력한다. **이 세 값이 `k eval`의 `progress`, `center`, `lap_time`과 소수 둘째 자리까지 같아야 한다.** 다르면 kit 판정과 5.5의 gate를 쓰지 않는다. 그 경우 `k official`의 결과로 판정하고(진행률 100.00, 랩타임 43.6초 이하, 중앙선 30 이상), 원인을 찾기 전에는 제출하지 않는다.

주행을 눈으로 보고 싶으면 본인 터미널에서 `.venv/bin/python scripts/infer.py configs/stage1.yaml`을 실행한다. `models/` 바로 아래에서 가장 최근에 저장된 모델을 주행시킨다.

### 5.5 gate 점검과 반복

5.4에서 합격한 체크포인트는 바로 gate를 돌린다(약 30초).

```bash
../pilot/kit/k gate $M.pth --json docs/logs/gate_$(basename $M).json | tee docs/logs/gate_$(basename $M).txt
```

주행 8개를 표로 보여 준다. 원래 주행 2개(`cuda`, `cpu`)와, 입력을 조금 바꾼 주행 6개(HUD 숫자 지우기 1개, ±2 픽셀 잡음 5개)다. 마지막 줄에 `gate PASS` 또는 `gate FAIL`이 나온다.

**PASS 조건**: `cuda`와 `cpu`가 깨끗하고 서로 같다. 바꾼 주행 6개가 모두 완주하고, 깨끗하지 않은 것이 1개 이하다.

파일럿 체크포인트로 돌려 본 예(출력은 `pilot/work/main/gate_examples/`에 있다):

| 체크포인트 | 원래 주행 | 바꾼 주행 6개 | 결과 |
|---|---|---|---|
| cnnA seed 0, 100 epoch | 깨끗함 (43.16초) | 6개 깨끗함 | PASS |
| cnnA seed 2, 100 epoch | 깨끗함 (43.20초) | 4개 깨끗함, 1개 진행률 99.62, 1개 중단 | FAIL |
| cnnA seed 6, 100 epoch | 진행률 98.93 | 6개 깨끗함 | FAIL |

seed 2처럼 원래 주행이 깨끗해도 조금만 달라지면 이탈하는 체크포인트가 있다. gate는 그런 것을 걸러 내는 용도이고, 통과가 서버 완주를 보장하지는 않는다. 평범하게 좋은 체크포인트도 열에 두세 번은 떨어질 수 있다(바꾼 주행의 실패율을 50개로만 재서 범위가 넓다).

**반복 규칙** (채택 = 5.4 합격 + gate PASS):

- 회차마다 5.3 학습 → 5.4 판정 → 합격이면 gate 순서로 한다. `start_model: scratch`라서 매번 독립된 학습이다.
- **채택 2개가 모이면 멈춘다.** 하나는 제출용, 하나는 예비다.
- **최대 5회까지** 한다. 설정 오류로 버린 학습은 횟수에 넣지 않는다.
- **처음 3회가 모두 5.4 불합격이면** 학습을 멈추고 6절의 교차 확인을 한다. 성공률이 3/4이면 3연속 실패는 1.6%지만, 3.5의 하한(0.4)에서는 22%까지 된다. 운일 수도 있으나 교차 확인이 싸므로 먼저 한다. 이상이 없으면 남은 2회를 이어서 한다.
- 불합격한 쌍도 지우지 않는다. 판정은 11절 표에 적는다.

주석만 바뀐 경우에는 오류 없이 주행한다. 그 차이는 5.6 (1)의 `cmp`에서만 드러난다.

처음 3회가 모두 불합격일 때의 교차 확인(공식 학습을 더 하지 않고 확인한다). 싼 것부터 (a) → (c) → (b) 순서로 한다.

## 7. 되돌리기와 파일 관리

- 제공 상태로 되돌리기: `git checkout HEAD -- src/network.py` (`assignment1/`에서 실행).
- 학습된 모델(`assignment1/models/`)은 git이 무시하지 않는다. `git add -A`, `git clean`을 쓰지 않는다.
- `assignment1/docs/`는 `.gitignore`의 `*/docs/`로 git에서 제외된다. 이 문서와 `docs/logs/`는 커밋되지 않으니 지우지 않도록 주의한다.
- `.pth`를 옮기거나 지울 때는 이름이 같은 `.network.py`도 함께 다룬다. 옮길 때는 `cp`가 아니라 `mv`를 쓴다(`latest`는 파일 수정 시각으로 최신을 고른다).
- 주행 코드는 현재 `src/network.py`로 모델을 만든다. 제출 쌍을 정한 뒤에도 `src/network.py`를 그 쌍의 `.network.py`와 같은 상태로 둔다.
- `src/network.py`를 바꾼 뒤에는 `baseline.pth`를 `infer.py`로 주행할 수 없다(구조가 달라 불러오기에서 멈춘다). 기준 수치 45.54초, 중앙선 51.03은 이미 기록돼 있으니 다시 잴 필요는 없다.

## 8. 1단계에서 하지 않는 선택지

1단계에서 채택하지 않은 선택지다. 첫 두 줄은 일부 측정이 있지만 결론을 낼 만큼은 아니고, 나머지는 측정이 없다. 필요할 때만 kit에서 실험한다.

| 선택지 | 현재 근거 | 실험 비용 |
|---|---|---|
| fc에서 숫자가 섞인 센서 입력 5개 제외 | 속도·ABS 센서 5개는 HUD의 점수 숫자 픽셀을 읽는다. 주행 때 그 숫자를 지우면 실패 10건이 깨끗해졌지만 깨끗하던 3건이 실패했다. 원인으로 확정되지 않았다 | 8 seed 학습 + 주행, 약 25분 |
| 계기판 영역을 잘라내는 층 추가 | cnnA에서는 효과가 없다(합성곱이 원래 그 영역을 읽지 않는다) | - |
| 더 작은 구조 | 측정 없음. cnnA도 CPU 1스레드에서 프레임당 1ms 미만이다 | 구조당 4 seed, 약 10분 |
| BatchNorm, Dropout, 폭 변경 | 측정 없음 | 구조당 4~8 seed |
| batch 64/128/512, 학습률 변경 | 측정 없음 | 설정당 4 seed |

seed 4개 비교에서 1~2개 차이는 잡음이므로, cnnA를 바꾸려면 8 seed 이상에서 큰 차이가 나와야 한다.

## 9. 확인이 필요한 질문 (조교 또는 제출 사이트)

- YAML의 `batch_size`, `start_model`을 바꾸는 것이 허용되는가. (이 계획은 허용된다고 가정한다. 제출물은 `network.py`와 `.pth`뿐이다.)
- 서버가 모델 크기, 추론 시간, 사용 가능한 층에 제한을 두는가.
- 제출 횟수 제한과 기한이 있는가, 최고 기록과 마지막 기록 중 무엇이 반영되는가.
- 진행률이 100 미만인 완주를 서버가 어떻게 처리하는가.
- 서버의 torch 버전이 2.10으로 저장한 `.pth`를 읽는가.
- 서버는 GPU와 CPU 중 무엇으로 주행시키는가. (로컬에서는 두 장치의 결과가 같았다.)

## 10. 2단계로 넘기는 관찰

- 전문가는 출발 후 12~32프레임(0.24~0.64초) 동안 아무것도 하지 않고, 모델도 그 대기(18~32프레임)를 따라 한다.
- 코너 안쪽으로 1만큼 붙을 때마다 줄어드는 시간은 최대 약 0.4초다(트랙 전체 회전각 ÷ 속도 상한으로 구한 상한).
- 데이터에 도로 복귀 동작이 없다. 도로를 길게 벗어나면 모델은 "아무것도 안 함"을 고르고 차가 멈춘다.
- cnnA의 합성곱은 영상 오른쪽 15열(81~95)을 읽지 않는다. 전문가 주행에서는 그 영역에 도로가 거의 없었지만, 주행 라인을 바꾸면 달라질 수 있다.
